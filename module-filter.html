01

Локальное исполнение на GPU

Ключевой принцип

Система разворачивается в инфраструктуре заказчика и выполняет все AI-операции на локальном GPU без передачи данных во внешние облачные сервисы.

Подход основан на принципе:

  • Детерминированная логика (FSM + правила) принимает решения.
  • Языковая модель используется только для классификации и понимания текста.
  • Результаты проходят проверку через verify/fix-контур.
  • При недоступности модели система продолжает работать по правилам.

Преимущества для заказчика

  • Соответствие требованиям 152-ФЗ и внутренней безопасности
  • Отсутствие зависимости от зарубежных API
  • Предсказуемая стоимость эксплуатации
  • Контроль над исходящими данными
02

Назначение модуля

Три задачи

Автоматическая оценка входящих запросов на предмет целесообразности подготовки КП.

  1. Отсекает заведомо нецелевые запросы.
  2. Возвращает запросы в отдел продаж с перечнем недостающей информации.
  3. Передаёт качественные запросы в модуль подготовки КП.

FAQ

Частые вопросы

Нужен ли доступ в интернет для работы модуля?

Нет. Классификация и правила выполняются на локальном GPU в вашей сети. Интернет нужен только для интеграций, если вы их включите.

Обязательна ли интеграция с Битрикс24?

Нет, но она даёт автоматический обмен сделками, статусами и журналом решений без ручного переноса данных.

Можно ли переопределить решение системы?

Да. Ответственный сотрудник может вручную изменить статус запроса — действие фиксируется в аудит-логе.

Сколько длится пилот?

Обычно 2–4 недели на исторических сделках: настройка правил, интеграция и калибровка метрик.
