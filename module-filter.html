Модуль фильтрации запросов

Автоматическая оценка входящих запросов на целесообразность подготовки КП — на локальном GPU, с правилами и интеграцией в Битрикс24.

1. Локальное исполнение на GPU (ключевой принцип)

Система разворачивается в инфраструктуре заказчика и выполняет все AI-операции на локальном GPU без передачи данных во внешние облачные сервисы.

Подход основан на принципе:

  • Детерминированная логика (FSM + правила) принимает решения.
  • Языковая модель используется только для классификации и понимания текста.
  • Результаты проходят проверку через verify/fix-контур.
  • При недоступности модели система продолжает работать по правилам.

Почему это важно

Преимущества для заказчика

  • Соответствие требованиям 152-ФЗ и внутренней безопасности.
  • Отсутствие зависимости от зарубежных API.
  • Предсказуемая стоимость эксплуатации.
  • Контроль над исходящими данными.

2. Назначение модуля

Автоматическая оценка входящих запросов на предмет целесообразности подготовки КП.

Модуль решает три задачи:

  • Отсекает заведомо нецелевые запросы.
  • Возвращает запросы в отдел продаж с конкретным перечнем недостающей информации.
  • Передаёт качественные запросы в модуль подготовки КП.

3. Что входит в поставку

  • Редактируемый набор правил фильтрации (без программирования).
  • Классификация неструктурированных запросов с помощью локальной языковой модели.
  • Интеграция с Битрикс24.
  • Журнал решений и причин отказа.
  • Ручное переопределение решения ответственным сотрудником.
  • Метрики работы фильтра.

4. Архитектура решения

Компонент Назначение
Rule Engine Основная логика принятия решений
Local LLM Classifier Извлечение признаков из текста
Verification Layer Проверка корректности классификации
Bitrix24 Integration Получение и обновление данных сделок
Audit Log Полная трассировка решений

Рекомендуемый стек: Python + LangGraph + Prefect/Temporal + PostgreSQL. Используется паттерн harness engineering, а не конкретный фреймворк reharness.

5. Ожидаемый результат

  • Снижение доли запросов, уходящих в подготовку КП, до 60–70%.
  • Сокращение потерь инженерного времени на заведомо слабые сделки.
  • Прозрачность причин отказов и возвратов.
  • Время обработки одного запроса — до 30 секунд.

6. Этапы внедрения

  1. Обследование и настройка правил.
  2. Интеграция с Битрикс24.
  3. Пилот на исторических сделках.
  4. Запуск в промышленную эксплуатацию.
